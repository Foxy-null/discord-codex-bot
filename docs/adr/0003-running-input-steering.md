# 実行中の追加入力を持続するCodex接続へ送る

作業スレッドへの追加入力で同じCodex会話を別プロセスから再開し、会話履歴のwriter競合が発生している。
実行中の作業に指示を追加できるよう、Workerが持続するApp
Server接続を所有し、待機中はターン開始、実行中はSteerを使う方式を提案する。
execの逐次実行なら競合は防げるが、入力が届くのは先行作業の終了後になるため、Steerの代替にはならない。

持続する接続では、入力の受理とターン完了を分け、完了時の返信と自動コミット・プッシュを一度だけ実行する必要がある。
接続方式の変更に伴い、停止、復旧、イベント解析、Worker破棄時の子プロセス回収も変更する。
通常送信をSteerにするかQueueにするかは未確定であり、この提案を採用済みとは扱わない。

調査根拠と具体的な変更箇所は[調査報告](../codex-follow-up-input-investigation.md)にまとめた。
