# 実行中の追加入力を持続するCodex接続へ送る

作業スレッドへの追加入力で同じCodex会話を別プロセスから再開し、会話履歴のwriter競合が発生している。
実行中の作業に指示を追加できるよう、Workerが持続するApp
Server接続を所有し、待機中はターン開始、実行中はSteerを使う方式を採用する。
execの逐次実行なら競合は防げるが、入力が届くのは先行作業の終了後になるため、Steerの代替にはならない。

持続する接続では、入力の受理とターン完了を分け、完了時の返信と自動コミット・プッシュを一度だけ実行する必要がある。
接続方式の変更に伴い、停止、復旧、イベント解析、Worker破棄時の子プロセス回収も変更する。
通常送信の既定はCodex
CLIのEnterに合わせてSteerとする。追加指示の受理を通知し、最終返信・成果物送信・命名・自動コミット・プッシュは元のターンの完了時に一度だけ実行する。
完了境界でSteerが明示的に拒否された場合は、後処理後の新しいターンへ渡す。接続障害などで受理の成否が不明な入力は自動再送しない。

自動コミットのメッセージ生成には、同じ接続内の独立した一時的なread-only会話を使う。生成結果はユーザー会話に追加しない。
停止は`turn/interrupt`で現在のターンだけを中断し、Worker破棄とBot停止で接続と子プロセスを回収する。
Workerの保存形式と`sessionId`を維持し、既存IDを`thread/resume`に渡す。復元失敗時に新規会話へ置き換えない。

2026年10月5日、ユーザーの実装指示を受けて採用。移行は既存の実行・自動コミット・プッシュを終えて旧Botを停止し、同じ実行ユーザー・`WORK_BASE_DIR`・`CODEX_HOME`で新Botを起動する。

調査根拠と具体的な変更箇所は[調査報告](../codex-follow-up-input-investigation.md)にまとめた。
